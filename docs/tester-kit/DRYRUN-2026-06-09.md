# Tester Kit — Dry-run #1 (2026-06-09)

키트(`wonik-ds-ai-context.md`) v1을 **실테스터 섭외 전 집에서** dogfood한 기록. office-hours 결정상 "테스터 고통 = polish backlog"인데, 그 proxy를 미리 돌려 키트 갭을 메웠다.

## 방법 (가짜 PASS 방지)
- **blind 에이전트 = 테스터의 AI 역할.** 키트 파일 **1개만** 읽게 하고 `packages/` 소스 열람 금지 → "설비 점검 요청 등록" 폼 화면을 짜게 함. 키트에 예시가 없던 컴포넌트(Tooltip·Modal 복합·Radio그룹·Switch·Checkbox·IconButton·ProgressBar·Avatar)를 강제로 쓰는 task.
- 나온 코드를 web-sandbox에서 **실제 `@wonik/web` 타입에 `tsc --noEmit`** + **negative control**(일부러 틀린 prop)로 타입 강제가 살아있음을 확인.

## 판정
- ✅ blind 생성 화면이 실제 타입에 **100% 클린 컴파일** (exit 0, `--listFiles`로 파일 포함 확인). → 키트만으로 신중한 AI가 정확한 코드를 뽑을 수 있음.
- ✅ negative control: `Button variant="틀린값"` → TS2322 잡힘, **`Tooltip label="x"` → TS2322 잡힘**. 즉 테스터 AI가 Tooltip 본문 prop을 `label`/`title`로 추측했으면 **진짜 깨졌다.** blind 에이전트는 `content`를 운으로 맞혀 통과한 것 → 문서화 필수임이 실측 증명.
- ⚠️ "컴파일은 되지만 의미가 틀린" 갭 존재: 에러 문구를 `<Text color="brand">`(=파랑)로 — Text엔 에러색이 없음.

## DS 레벨 backlog (키트가 아니라 DS 자체의 갭 — 진짜 polish 후보)
- **Text에 에러용 색이 없다.** 필드 단위 빨강 에러 텍스트가 first-class 패턴 아님 → 현재는 `Alert`로 우회. 폼이 많아지면 `Text color="alarm"` 또는 Input `errorText` slot 검토.
- **Badge 상태 팔레트 2개뿐**(neutral/primary). 경고(노랑)·위험(빨강) 상태 라벨 불가. status 토큰(`statusTokens`)은 있으나 Badge로 안 뚫림.
- **레이아웃 width/height 토큰·prop 없음** — 의도된 미니멀일 수 있음(레이아웃은 style로). 확정 필요.
- **DS가 아이콘을 제공 안 함** — 의도된 결정으로 보이나(host가 가져옴) ADR로 못박은 적 없음.

→ 이 4개는 **실테스터가 같은 곳에서 막히면** 우선순위가 올라간다. 지금은 키트 문서로 우회 가능하므로 DS 변경은 보류(ADR-001).
